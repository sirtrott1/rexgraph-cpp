# Native gluing

Two filled triangles share a declared edge and its complete occurrence fiber.
Their pushout has four vertices, five edges and two faces. Equal raw keys outside
the interface remain separate. Inactive, zero and cancelling occurrences survive
with their full original source maps.

```sh
cmake -S examples/native_gluing -B build/native_gluing -G Ninja \
  -DRFC_SOURCE_DIR="$PWD"
cmake --build build/native_gluing --parallel 1
build/native_gluing/native_gluing
```

For an installed library, replace `RFC_SOURCE_DIR` with `CMAKE_PREFIX_PATH`.

`PreparedNativeGluing` prepares the existing native atlas constructor once and
owns its three original publications, complete interface maps and materialized
source. Its algebraic plan checks the whole source square, including coverage,
the precise common intersection, full occurrence fibers and strict chain laws.
The bounded profile uses one fixed signature and semantic scale.

`glue_sections` requires complete scalar sections and a declared field identity.
Common values must agree and are retained once. `include` instead pushes a local
chain into the pushout. These are different operations. Boundary actions retain
every encountered lower coordinate, including zero results.

`PreparedNativeGluingMorphism` checks two complete strict source maps into an
actual target publication. Agreement on all common cells and occurrences gives
the unique map from the pushout. Its chain action can add contributions when the
declared target map identifies different source cells; supported cancellation
remains present. Output owns the full maps, target and input history.

Every action checks explicit current cutoffs and resource limits. Source and
field views remain bound to their actual owning publication and authority.
Canonical materialization observes cancellation at its synchronous call
boundaries; certification and actions have finer checkpoints. Counts describe
named containers and visits, rather than process memory or elapsed time.
Recodings, heterogeneous tensor stalk gluing, metric extensions, GPU kernels and
publication of the prospective pushout require separate contracts.
